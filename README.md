# publish-guard(公開の前後に確かめる道具)

Claude Code 用のプラグインです。名前は仮です。

フォルダ・リポジトリ・文章を外に出すときに、Claude が「出す前に検索する → 出したあとに突き合わせる → 記録する」を決まった手順で行うためのスキル4つと、そのためのスクリプトを入れてあります。どれも**止める側に倒して**あり、見つけたものを勝手に直しません。

## 何をするか

| スキル | 内容 | 動かすもの |
|---|---|---|
| `prepublish-scan` | 出す前の検索。鍵・トークンの形、メールアドレス、絶対パス、自分で決めた検索語(勤め先名・本名など)、git の作者メール、履歴(過去の差分とコミットの文面)を調べ、「重大度・種類・場所」の表を出す。NG が1件でもあれば「公開しない」と答える | `scripts/scan.sh`・`scripts/selftest.sh` |
| `publish-verify` | 新しい公開リポジトリ(と GitHub Pages)を出すときの関門と突き合わせ。作者メールが匿名用でなければ止める。出したあとに clone して `cmp` で1ファイルずつ比べ、公開先の作者メールも確かめ、記録を書く | `scripts/publish-verify.sh` |
| `claim-check` | 文章の中の「日付と出典のない数字」と「保証表現」を検出し、「行・語・理由」の表を出す。検出だけで、文は直さない。語は足せる | `scripts/claim_check.py` |
| `expert-question-list` | お金・人の情報・広告表示などに関わる企画について、専門家や公式の窓口に**聞く項目**を質問の表にする。助言ではない。答え・判断・条文の説明は出さない | (スクリプトなし。確かめに `claim_check.py` を使う) |

使う順の目安: 文章は `claim-check` → 出すフォルダは `prepublish-scan` → 出すときは `publish-verify`。企画の段階で `expert-question-list`。

## 入れ方

手元のフォルダから試すとき:

```
claude --plugin-dir ./publish-guard
```

マーケットプレイスに登録してある場合は、そこから入れます(`/plugin install publish-guard@<マーケットプレイスの名前>`)。

必要なもの: `bash`・`git`・`grep`・`awk`・`curl`(`publish-verify` の Pages 比較)・`python3`(`claim-check`)。GitHub に公開するときは `gh`(ログインは自分で済ませておく)。

## 使い方

Claude に、たとえば次のように頼みます。

- 「このフォルダ、公開前チェックして」
- 「新しいリポジトリで公開して、Pages と手元が同じか確かめる所まで」
- 「この原稿に、出典のない数字や保証表現がないか見て」
- 「この企画で、専門家に聞いておくことを表にして」

スクリプトを直接動かすこともできます(下の命令は、このプラグインのフォルダに移動してから実行する場合の書き方です)。

```bash
bash skills/prepublish-scan/scripts/scan.sh <出すフォルダ> --history
```
```bash
bash skills/publish-verify/scripts/publish-verify.sh pre <出すフォルダ>
```
```bash
bash skills/publish-verify/scripts/publish-verify.sh post <出すフォルダ> <リポジトリのURL> --pages <PagesのURL> --record <記録ファイル>
```
```bash
python3 skills/claim-check/scripts/claim_check.py <文章ファイル>
```

### 自分用の設定(このプラグインの外に置く)

設定フォルダは、既定で `~/.config/publish-guard/`(環境変数 `PUBLISH_GUARD_CONFIG` か `--config` で変えられます)。

| ファイル | 中身 | 見本 |
|---|---|---|
| `terms.txt` | 出したくない語(勤め先名・本名・アカウント名など)。1行1語 | `skills/prepublish-scan/examples/terms.example.txt` |
| `claim-words.txt` | 足したい保証表現の語。1行1件「語<TAB>理由」 | `skills/claim-check/examples/claim-words.example.txt` |

**`terms.txt` は、公開するフォルダにも git にも入れないでください。** その語の一覧そのものが個人の情報になります。同梱の見本は、全部架空の語です。`terms.txt` がないと、勤め先名・本名などは検索されません(そのときは表に WARN として出ます)。

## やらないこと

- **見つけたものを直しません・消しません。** 検索と比較は読むだけです。
- **例外の許可を登録する仕組みはありません。** 「このメールは出してよい」「このNGは無視」と覚えさせる方法は、わざと入れていません。出してよい連絡先のメールも NG になります(見本用の `@example.com` などと、匿名用の `…@users.noreply.github.com`・`noreply@…` を除く)。
- **履歴の書き換えをしません。** 作者メールや過去の差分に問題が見つかったら、新しいリポジトリで作り直す案を示すだけです。
- **既存のリポジトリへの公開には使えません。** `publish-verify` の関門は、リモートが設定済みのフォルダを止めます。
- **公開・push・Pages の有効化を、承認なしに行いません。** スクリプトには作成や push の命令は入っていません。スキルの手順では、Claude がそのたびに承認を取る決まりにしてあります。
- **文を直しません。** `claim-check` は検出だけです。出典を作ったり、推測で足したりしません。
- **法律の助言をしません。** `expert-question-list` が出すのは質問だけです。決まりが当てはまるか、してよいかは答えません。
- フック(決まったきっかけで自動的に動く仕組み)・MCPサーバーは入っていません。push の前にひとりでに検索が走ることはありません。スキルが読まれるかどうかは、Claude の判断です(当てはまる依頼でも読まれないことがあります。割合は測っていません)。
- 外部への通信は、`publish-verify.sh post` が、指定された公開先から clone と取得を行うときだけです。

## 確かめたこと・未確認のこと

確かめたこと(2026-11-23、macOS・bash 3.2・git・Python 3.10。入力は全部架空):

| スキル | 確かめたこと |
|---|---|
| `prepublish-scan` | `selftest.sh` で、架空の混入9種類(トークンの形・絶対パス・メール・秘密鍵のブロック・自分用の検索語・秘密を入れやすいファイル名・秘密らしい代入・作者メール・履歴だけに残る鍵)が9種類とも表に出た。混入なしは NG 0・WARN 0。見つかった値は出力に出ない。実行の前後で対象のファイルは変わらない |
| `publish-verify` | 手元の模擬リポジトリで、匿名でない作者は関門で止まる/正常なら関門が全部 OK/公開先と一致で「差分 0」・終了コード 0/手元を1文字変えると「中身が違う」・終了コード 1/リモート設定済みは止まる。GitHub の新しい公開リポジトリ1つ(架空の見本3ファイル)と Pages でも、clone と Pages の両方で「3ファイル、差分 0」、公開先の作者は匿名用 |
| `claim-check` | 同梱の見本の原稿(仕込み5か所)で、5か所とも表に出た。日付と出典のある段落の数字は出ない。混入なしは 0 件。足した語が検出に加わる。原稿は書き換わらない |
| `expert-question-list` | 架空の企画1つで質問12個の表を作り、言い切りの形(`references/assertion-words.txt`)が 0 件。1行目に「助言ではない」の文がある |

未確認のこと:

- Linux・Windows での動作。GNU の `grep`・`awk`・`sed` での動作。
- 大きなリポジトリで `--history` にかかる時間。
- GitHub 以外の公開先(`post` は clone できるURLなら動く作りだが、確かめていない)。
- 実際の長い原稿での `claim-check` の当たりすぎ・見逃しの割合。
- `expert-question-list` の質問の種(`references/topics.md`)の**内容の正確さ・網羅**。専門家の確認を受けていません。
- 検索はパターンとの一致だけです。画像・PDF・Excel の中身、文脈で分かる個人情報、形の決まっていない秘密は見つかりません。**0件は「問題がない」ことの証明ではありません。**
