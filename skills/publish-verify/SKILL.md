# 公開と突き合わせ

「push が通った」は完了ではない。完了は「公開先から取り直したものが、手元と1バイトも違わず、作者欄に個人のメールがなく、その記録が残っている」まで。

## 決まり

- **新しいリポジトリだけ**。すでにリモートがあるフォルダ、すでに公開先にある名前には使わない(過去の履歴ごと出てしまう)。
- **作者・コミッターのメールが匿名用(`…@users.noreply.github.com`)以外なら止める**。履歴の書き換え(rebase・filter・force push)は、このスキルでは行わない。新しいフォルダで作り直す案を示す。
- **公開・push・Pages の有効化は、そのたびにユーザーの承認を取ってから**。関門が全部 OK でも、承認の代わりにはならない。許可を求める操作が断られたら、別の方法で通そうとせず、止めて報告する。
- 関門が NG なら公開しない。例外は作らない。
- アカウントの作成・ログイン・トークンの入力はしない(ユーザーが行う)。

## 手順

> 下の命令の `<このスキルのフォルダ>` は、この SKILL.md があるフォルダ(スキルを読み込んだときに示される場所)に置き換える。作業中のフォルダからの相対の場所ではない。

スクリプトは、このスキルのフォルダの `scripts/publish-verify.sh`。公開前の検索は、同じプラグインの `prepublish-scan` を中から呼ぶ。

### 1. 出すものだけの新しいフォルダを作る

出すファイルだけを新しいフォルダに写し、そこで `git init` する。先にメールを匿名用にしてから、最初のコミットをする。

```bash
git init -b main .
git config user.email "<ID>+<ユーザー名>@users.noreply.github.com"   # 値はユーザーのGitHubの設定画面にある
git add -A && git commit -m "最初の版"
```

匿名用メールの値が分からなければ、ユーザーに設定してもらう(推測で作らない)。

### 2. 関門(pre)

```bash
bash "<このスキルのフォルダ>/scripts/publish-verify.sh" pre <フォルダ>
```

確かめる項目: リポジトリの最上位/コミットがある/未コミットの変更がない/リモートが未設定/`user.email` が匿名用/全コミットの作者・コミッターが匿名用/公開前の検索(履歴も)で NG 0。終了コード 1 なら「公開しない」と伝えて止まる。WARN が出たら1件ずつ目で確かめる。

公開先に同じ名前がないことも確かめる(例: `gh repo view <所有者>/<名前>` が「見つからない」になる)。

### 3. 承認を取って公開する

公開する名前・公開範囲(だれでも見られる)・Pages を使うかを示し、ユーザーの承認を取る。承認の範囲だけ実行する。GitHub の例:

```bash
gh repo create <名前> --public --source . --push
gh api -X POST repos/<所有者>/<名前>/pages -f 'source[branch]=main' -f 'source[path]=/'   # Pages を使うときだけ
```

### 4. 突き合わせ(post)と記録

```bash
bash "<このスキルのフォルダ>/scripts/publish-verify.sh" post <フォルダ> <リポジトリのURL> --pages <PagesのURL> --record <記録ファイル>
```

- 一時フォルダに clone し、最新のコミット・全ファイルの `cmp`・公開先の全コミットの作者メールを確かめる。
- `--pages` を付けると、Pages から各ファイルを取って `cmp` で比べる。Pages は反映に数分かかることがある。「取れない」が出たら数分待ってもう一度(同じ再実行は3回まで。それでも駄目なら「Pages は未確認」と記録する)。
- 終了コード 0(差分 0・作者は全部匿名用)のときだけ「公開を確かめた」と言う。それ以外は「未完了」とし、原因が分かるまで完了にしない。
- 記録は `--record` のファイルに書き足される。ほかの欄(承認・未確認)は `references/record-template.md` の様式で手で足す。記録には、値(メール・鍵)と手元の絶対パスを書かない。

### 5. 報告

公開先のURL、差分の数、作者メールの結果、記録ファイルの場所、未確認の範囲を伝える。

## 限界

- Pages の比較は、名前が `.` か `_` で始まるファイル・フォルダと、空白入りの名前を飛ばす(Pages が配らない、またはURLにしにくいため)。
- 比べるのは git で管理しているファイルだけ。
- GitHub 以外の公開先では、手順3の命令は読み替える。post は、clone できるURLなら動く。確かめたのは GitHub と手元の模擬リポジトリだけ。
- 関門と突き合わせが通っても、中身が「出してよいもの」かどうかの判断にはならない。
