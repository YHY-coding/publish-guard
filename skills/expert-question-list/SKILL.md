# 専門家に聞く項目の整理

**これは助言ではない。専門家に聞く項目の整理である。** 出すものは質問の表だけで、答え・判断・条文の説明は出さない。このスキルの中身(質問の種)の正確さは、作者も確かめていない。

## 決まり

- 出力の**1行目**に、次の文をそのまま書く: 「これは助言ではありません。専門家に聞く項目の整理です。」
- **言い切りを書かない**。「〜に当たります」「〜が必要です」「〜は問題ありません」「違法/適法」、条文の番号、罰則の話を書かない。知っているつもりの決まりも書かない(古い・まちがっているおそれがある)。
- 書くのは**質問**(「〜か。」で終わる文)と、**企画のどの部分がきっかけか**と、**先にそろえる事実**だけ。
- 「結局やってよいのか」と聞かれても、判断を答えない。「それを専門家に聞くための表です」と返し、いちばん先に聞くとよさそうな項目を示すにとどめる。
- 実在の専門家・事務所の名前を挙げない(相手の種類だけ)。

## 手順

> 下の命令の `<このスキルのフォルダ>` は、この SKILL.md があるフォルダ(スキルを読み込んだときに示される場所)に置き換える。作業中のフォルダからの相対の場所ではない。

1. **企画の事実を集める**。足りなければ短く聞く: だれに/何を/お金の流れ(だれがだれに払うか・預かるか)/集める情報と置き場所/外部に渡る先/うたい文句/売り方(無料・都度・月額)/個人か法人か。分からない所は「未定」と書く(推測で埋めない)。
2. **`references/topics.md` を読み**、企画に「きっかけ」が当てはまる分野だけを選ぶ。当てはまらない分野は入れない。
3. **質問を企画の言葉に書き換える**。種の文をそのまま並べない。1分野につき多くて4つ。全体で15個以内を目安にする。
4. **表にして出す**(下の形)。
5. **言い切りがないことを確かめる**。出力をファイルに保存し、同じプラグインの `claim-check` のスクリプトで調べる(同じプラグインの隣のスキルにある):
   ```bash
   python3 "<このスキルのフォルダ>/../claim-check/scripts/claim_check.py" <出力ファイル> --no-numbers --no-default-words --words "<このスキルのフォルダ>/references/assertion-words.txt"
   ```
   「検出 0 件」になるまで、当たった文を質問の形に直す。スクリプトが使えない環境では、`references/assertion-words.txt` の形を目で探す。
6. 表の下に「未定の事実」と「この表にない分野があるかもしれない」ことを書く。

## 出力の形

```
これは助言ではありません。専門家に聞く項目の整理です。

対象の企画: <1〜2行。事実だけ>

| # | 分野 | 聞くこと | きっかけ(企画のどの部分か) | 先にそろえる事実 | 聞く相手の種類 |
|---|---|---|---|---|---|
| 1 | … | 〜か。 | … | … | … |

未定の事実: <聞く前に決める・調べること>
この表は、聞く項目の整理です。ここにない分野が関係することもあります。答えは、専門家か公式の窓口に確かめてください。
```

## 似たスキルとの分け方

法務部門向けの確認スキル(当てはまる規制の洗い出し、リスクの評価、契約の審査など)が別に入っている場合、判断や評価はそちらと専門家の役目。このスキルは、専門の担当がいない個人・小さな集まりが「何を聞けばよいか」を1枚にする所までしか行わない。

## 追加の資料

- `references/topics.md` — 分野ごとの「きっかけ」と質問の種、聞く相手の種類
- `references/assertion-words.txt` — 言い切りの形(確かめ用)
- `examples/sample-output.md` — 架空の企画での出力の見本
