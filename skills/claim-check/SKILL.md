# 数字・出典・保証表現の検出

役目は**検出だけ**。文を書き換えない。直すかどうか、どう直すかは書いた人が決める。

## 手順

> 下の命令の `<このスキルのフォルダ>` は、この SKILL.md があるフォルダ(スキルを読み込んだときに示される場所)に置き換える。作業中のフォルダからの相対の場所ではない。

1. 対象の文章ファイルを確かめる(Markdown かテキスト)。会話に貼られた文章なら、一時ファイルに保存してから調べる。
2. 実行する(このスキルのフォルダの `scripts/claim_check.py`。Python 3 の標準機能だけで動く):
   ```bash
   python3 "<このスキルのフォルダ>/scripts/claim_check.py" <ファイル>...
   ```
3. 出た表を**そのまま**見せる。行を勝手に減らさない・理由を言い換えない。
4. 表のあとに、行ごとの見立てを短く添えてよい(例: 「15行目は否定の文なので、そのままでよさそう」)。見立ては見立てと分かるように書く。
5. 文の直しは、頼まれたときだけ、案として示す。対象のファイルを書き換えない。出典を作らない・推測で足さない(出典が分からない数字は「出典なし」のままにし、消すか、確かめるかを書いた人に聞く)。

## 何を検出するか

| 種類 | 当たる条件 | 表の理由 |
|---|---|---|
| 数字 | 単位つきの数字(%・円・人・件・倍・時間・か月 など)があり、**同じ段落**(空行までのまとまり)に日付か出典の印がない | `数字: 同じ段落に日付と出典がない`(片方だけ欠けていれば、その片方) |
| 保証表現 | 語のリストに当たる | `保証表現: <理由>`。同じ文に否定の形があれば「否定の文の中かもしれない」と添える(それでも表には出す) |

- 日付の印: `2026年10月`、`2026-10-01`、`令和8年`、`10月1日` など。
- 出典の印: 「出典」「出所」「参照」「〜によると」「公表」「公式」「統計」、URL、脚注の印(`[^1]`・`※1`)など。
- コードの囲み(```)の中、URL、`バッククォート` の中は調べない。全角の数字・記号は半角にそろえてから調べる。

## 語を足す

同梱の語は `references/guarantee-words.txt`。分野ごとの語は、同梱のファイルを書き換えずに足す:

- いつも使う語: 設定フォルダ(既定 `~/.config/publish-guard/`。`--config` か環境変数 `PUBLISH_GUARD_CONFIG` で変えられる)に `claim-words.txt` を置く。
- その場だけ: `--words <ファイル>`(何回でも)。
- 書き方は `examples/claim-words.example.txt`(1行1件「語<TAB>理由」。`re:` で始めると正規表現)。

そのほか: `--no-default-words`(同梱の語を使わない)、`--no-numbers`(数字を調べない)。

## 確かめ用の見本

`examples/sample-draft.md` は、仕込みを5か所入れた架空の原稿。次を実行すると、5・7・11・13・15 行目が表に出る(日付と出典のある 9 行目は出ない)。

```bash
python3 "<このスキルのフォルダ>/scripts/claim_check.py" "<このスキルのフォルダ>/examples/sample-draft.md"
```

## 限界

- 形と語の一致を見るだけ。出典が**本物か**、数字が**正しいか**は確かめない。
- 「同じ段落に日付と出典の印があるか」で見るため、別の数字の出典が同じ段落にあると見逃す。離れた場所(記事の末尾など)にまとめて出典を書く形だと、全部が当たる。
- 単位のない数字、漢数字、画像の中の数字は調べない。
- 語の一致なので、別の意味の語にも当たることがある(同梱の語では「絶対パス」「保証表現」「無保証」を外してある)。当たりすぎる語は、`--no-default-words` と自分の語のファイルで調整する。
- 保証表現は語のリストにあるものだけ。言い回しを変えた約束(「まず失敗は考えられません」など)は見つからない。
- 終了コード: 0 = 検出なし / 1 = 検出あり / 2 = 使い方の誤り。0 でも「内容に問題がない」ことにはならない。
